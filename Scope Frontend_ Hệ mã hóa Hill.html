1Mục tiêu Frontend

Thêm Hill vào công cụ mã hóa, dùng lại bố cục kiểu jwt.io và các component đầu vào của tuần Caesar. Người dùng nhập văn bản, nhập khóa ma trận, thấy ngay khóa có hợp lệ không, rồi mã hóa/giải mã và xem từng bước tính để phục vụ báo cáo và demo.

Yêu cầu dự án Phần việc của FE
Có giao diện Tab Hill: trái là văn bản và khóa, phải là kết quả và phân tích khóa.
Đầu vào từ file hoặc bàn phím Textarea + tải file .txt (đọc ở client, UTF-8, ≤ 1 MB). Khóa nhập dạng lưới hoặc từ khóa.
Mã hóa và giải mã Gọi API BE, hiển thị kết quả tô màu theo khối.
Bắt lỗi và thông báo Kiểm tra định dạng tại client, hiển thị lỗi BE đúng chỗ, đúng câu (mục 7).

2Kiến thức cần nắm

  • Chữ cái ↔ số: A=0 … Z=25. Văn bản chia thành khối m chữ, mỗi khối là vector hàng x.
  • Mã hóa: y = x·K mod 26. Giải mã dùng K⁻¹ thay cho K.
  • Khóa chỉ hợp lệ khi det K mod 26 là số lẻ và khác 13. FE không tự tính mật mã, nhưng cần hiểu để trình bày panel phân tích khóa.
  • Quy ước màu dùng xuyên suốt giao diện: xanh dương = bản rõ, hồng = khóa, xanh lá = bản mã (giống cách jwt.io tô header/payload/signature).

Chi tiết thuật toán, API và mã lỗi đầy đủ nằm ở scope Backend.

5Luồng tương tác

  1. Mở tab HillKhóa mặc định [[3,3],[2,5]], văn bản giữ từ tab trước. Gọi /key/analyze một lần.
  2. Sửa khóaKiểm tra định dạng tại client (số nguyên, đủ ô). Hợp lệ về định dạng thì gọi /key/analyze với debounce 300 ms; hủy request cũ khi có request mới.
  3. Đổi mDựng lại lưới m×m, điền khóa ngẫu nhiên hợp lệ từ /key/random.
  4. Nhập văn bảnGõ tay hoặc tải .txt. File được đọc ở client, kiểm tra đuôi, kích thước, UTF-8 trước khi đưa vào textarea.
  5. Bấm Mã hóa / Giải mãNút bị khóa khi văn bản rỗng hoặc khóa chưa hợp lệ. Hiện trạng thái đang xử lý trên ResultPanel.
  6. Nhận kết quảHiển thị văn bản kết quả, tô màu theo khối, cảnh báo W01/W02/W03 nếu có. Lỗi hiển thị tại đúng vùng gây lỗi.
  7. Xem từng bước / xuất kết quảMở StepViewer, sao chép hoặc tải kết quả .txt.

6Tích hợp API

Endpoint Gọi khi Dùng dữ liệu nào
POST /api/hill/key/analyze Khóa đổi và đúng định dạng (debounce 300 ms) det, detInverse, adjugate, inverse cho KeyAnalysisPanel
GET /api/hill/key/random?m= Bấm "Khóa ngẫu nhiên", đổi m key điền vào lưới
POST /api/hill/encrypt Bấm "Mã hóa" result, blocks, warnings
POST /api/hill/decrypt Bấm "Giải mã" result, blocks, warnings 
// Request mã hóa
{ "text": "HELP", "key": [[3,3],[2,5]], "options": { "stripDiacritics": false, "padChar": "X" } }

// Response 200
{ "result": "DPLE",
  "blocks": [ { "input": [7,4], "output": [3,15] }, { "input": [11,15], "output": [11,4] } ],
  "key": { "m": 2, "det": 9, "detInverse": 3, "adjugate": [[5,23],[24,3]], "inverse": [[15,17],[20,9]] },
  "warnings": [] }

// Response 422
{ "error": { "code": "E04", "message": "...", "details": { "det": 2, "gcd": 2 } } }

Chế độ từ khóa: gửi "keyword": "HILL" thay cho key. Lỗi mạng hoặc 5xx hiển thị: "Không kết nối được máy chủ. Thử lại." kèm nút "Thử lại".

7Hiển thị lỗi và cảnh báo

Mã Ai phát hiện Hiển thị ở đâu Thông báo
E01 FE Dưới textarea; khóa nút chính Nhập văn bản hoặc tải file .txt để bắt đầu.
E02 BE ResultPanel Văn bản không có chữ cái nào để mã hóa. Hill chỉ xử lý A–Z.

11Tiêu chí nghiệm thu Frontend

  • Pass toàn bộ UI01–UI13.
  • Tab Hill thống nhất giao diện với tab Caesar; đổi tab không mất văn bản.
  • Khóa không hợp lệ luôn bị chặn trước khi gọi mã hóa/giải mã, lý do hiển thị rõ.
  • Panel phân tích khóa hiển thị det, (det)⁻¹, K*, K⁻¹ khớp dữ liệu BE.
  • Mọi mã lỗi/cảnh báo hiển thị đúng vị trí và đúng câu ở mục lỗi.
  • Dùng được trên màn hình 375 px và hoàn toàn bằng bàn phím.

12Ngoài phạm vi

  • Giao diện tấn công bản rõ đã biết, Affine-Hill, m lớn hơn 4.
  • Lưu lịch sử, đăng nhập, chia sẻ kết quả qua link.
  • Tự tính mật mã ở client để chạy offline (FE chỉ gọi BE).
