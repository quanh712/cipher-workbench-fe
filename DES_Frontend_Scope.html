1. Mục tiêu feature

Xây dựng màn hình DES đồng bộ với Caesar hiện tại trong Cipher Workbench, cho phép người dùng: nhập văn bản hoặc tải file, nhập DES key, chọn Encrypt/Decrypt, gửi request tới backend và xem kết quả.

Frontend chịu trách nhiệm
  • Render giao diện DES.
  • Quản lý text/file/key/operation.
  • Validate cơ bản trước khi gọi API.
  • Gọi DES API và map response.
  • Loading, error, success state.
  • Copy/Clear/Download output nếu pattern Caesar đang có.
  • Responsive và đồng bộ UI với các cipher khác.
Frontend không xử lý
  • Không tự implement DES core.
  • Không tự sinh K1...K16.
  • Không tự chạy IP / S-box / Feistel.
  • Không tự quyết định padding/mode nếu BE chưa chốt contract.
  • Không tự sửa ciphertext trả về từ BE.

2. UI Scope

2.1. Layout

Giữ cùng bố cục và component style với Caesar để toàn bộ Cipher Workbench đồng nhất.

Algorithm Header: DES → Input Panel → Settings / Key → Action → Output Panel

2.2. Thành phần bắt buộc

Component Yêu cầu FE
Algorithm title Hiển thị DES / Data Encryption Standard, đồng bộ heading với Caesar.
Mode selector Encrypt / Decrypt, dùng đúng component/pattern của Caesar nếu đã có.

UI consistency rule:

Không tạo một giao diện DES hoàn toàn mới. Ưu tiên reuse component, spacing, border, typography, tab/button và result panel đang dùng ở Caesar.

3. User Flow

3.1. Encrypt Text

Chọn DES→ Encrypt→ Text→ Nhập plaintext→ Nhập key→ Submit→ Result

3.2. Decrypt Text

Decrypt→ Nhập ciphertext→ Nhập cùng key→ Submit→ Plaintext result

3.3. File

File mode→ Upload file→ Nhập key→ Encrypt / Decrypt→ BE response→ Preview / Download

4. State Management

State tối thiểu của DES screen:

operation: "encrypt" | "decrypt"
inputMode: "text" | "file"

inputText: string

4.1. Reset rule

  • Đổi operation không bắt buộc xóa input, nhưng phải clear lỗi cũ.
  • Đổi Text ↔ File phải tránh submit đồng thời cả hai nguồn input.
  • Khi request mới bắt đầu: clear error cũ và xử lý result theo pattern chung của app.
  • Clear phải reset input, file, key, result và message liên quan.

5. Frontend Validation

FE validate để UX tốt hơn, nhưng BE vẫn là nguồn validation cuối cùng.

Case FE behavior
Không có text/file Không submit; hiện lỗi cạnh vùng input.
Key rỗng Không submit; focus vào key field.
Key sai format theo API contract Hiển thị helper/error message; không tự sửa key.
File không hợp lệ Không gọi API; hiển thị lỗi file.
Đang request Disable action button để tránh double submit.
Không hard-code format key trước khi BE chốt.

Slide mô tả DES với key 64 bit, ví dụ dạng hexadecimal. FE chỉ nên enforce đúng format mà BE contract quy định: ví dụ 16 hex characters hoặc dạng khác.

6. API Integration Scope

6.1. Text request

POST /api/des/encrypt
{
  "text": "...",
  "key": "..."
}

POST /api/des/decrypt
{
  "text": "...",
  "key": "..."
}

6.2. File request

POST /api/des/file
Content-Type: multipart/form-data

file
key
operation = encrypt | decrypt

6.3. FE service

desService.encryptText(payload)
desService.decryptText(payload)
desService.processFile(formData)

Endpoint/tên field ở trên là contract mục tiêu. Nếu BE hiện tại dùng naming khác, FE service adapter phải map ở một chỗ, không rải request logic trực tiếp trong component.

7. File Handling

  • Dùng cùng upload component với Caesar nếu component đã reusable.
  • Chỉ giữ một file tại một thời điểm nếu requirement hiện tại giống Caesar.
  • Hiển thị file name và trạng thái đã chọn.
  • Có thao tác remove/replace file.
  • Không đọc/chuyển đổi DES ở client; file được gửi cho backend xử lý.
  • Nếu BE trả Blob: tạo download action ở FE.
  • Nếu BE trả text: hiển thị trong result panel.

8. Loading, Error & Result States

Loading

  • Disable Encrypt/Decrypt button.
  • Hiển thị spinner/loading text theo design hiện tại.
  • Không cho spam request.

Error

  • Ưu tiên message từ BE.
  • Nếu network error: hiển thị message fallback dễ hiểu.
  • Không render raw stack trace hoặc object lỗi.
  • Lỗi field-level đặt gần input tương ứng nếu xác định được.

Result

  • Result readonly.
  • Không trim hoặc tự sửa dữ liệu ciphertext/plaintext trả về.
  • Copy phải copy chính xác result.
  • Nếu result rỗng, giữ empty state thay vì hiện dữ liệu request cũ.

9. Algorithm Information trên UI

FE có thể có phần mô tả ngắn giúp người dùng hiểu DES, nhưng không cần hiển thị toàn bộ tính toán 16 vòng trừ khi project có yêu cầu visualization.

Nội dung mô tả đủ dùng:

DES xử lý dữ liệu theo block 64 bit, sử dụng cấu trúc Feistel 16 vòng. Mỗi vòng dùng một khóa con 48 bit sinh từ khóa ban đầu.

Theo tài liệu bài giảng: sau IP, dữ liệu được chia thành L0/R0; mỗi vòng dùng Li = Ri-1 và Ri = Li-1 XOR f(Ri-1, Ki), sau vòng 16 swap R16/L16 rồi áp dụng IP⁻¹.

11. Chia task Frontend

  1. FE-DES-01 – Route / Algorithm registration: thêm DES vào danh sách/route/menu cipher.
  2. FE-DES-02 – DES screen: dựng layout theo Caesar.
  3. FE-DES-03 – Operation state: Encrypt / Decrypt.
  4. FE-DES-04 – Input source: Text / File.
  5. FE-DES-05 – Key field: input + helper + validation.
  6. FE-DES-06 – API service: encrypt/decrypt/file.
  7. FE-DES-07 – Loading/Error: xử lý request lifecycle.
  8. FE-DES-08 – Result actions: copy/clear/download theo behavior chung.
  9. FE-DES-09 – Responsive/UI sync: đồng bộ spacing, size, alignment với Caesar.
  10. FE-DES-10 – Test: component/service/validation và manual E2E.

12. Acceptance Criteria / Definition of Done

  • DES xuất hiện đúng trong navigation/algorithm selector của Cipher Workbench.
  • Màn DES đồng bộ giao diện với Caesar, không lệch kích thước panel/control vô lý.
  • Người dùng chọn được Encrypt hoặc Decrypt.
  • Người dùng dùng được cả Text và File input.
  • Key field có validation theo đúng BE contract.
  • Không submit khi input/key chưa hợp lệ.
  • Request đi qua DES service riêng, không gọi API trực tiếp rải rác trong UI component.
  • Có loading state và chống double submit.
  • BE error được hiển thị dễ hiểu.
  • Result hiển thị nguyên vẹn và copy chính xác.
  • File response download được nếu BE trả file.
  • Clear/reset hoạt động đúng.
  • Responsive trên desktop/mobile theo layout hiện có.
  • Không implement DES algorithm ở frontend.

13. Out of Scope

  • Implement DES cryptographic core trong browser.
  • Hiển thị toàn bộ 16 round chi tiết nếu chưa có requirement.
  • Tự sinh hoặc brute-force key.
  • DES key cracking / cryptanalysis.
  • 3DES.
  • AES hoặc cipher khác.
  • User history / database / authentication.

14. Điểm cần đồng bộ với Backend trước khi hoàn thiện

  • Key format chính xác: HEX 16 ký tự hay format khác.
  • Ciphertext trả về: HEX, Base64 hay text khác.
  • Mode/padding cho dữ liệu dài hơn một DES block.
  • Endpoint và DTO chính thức.
  • File types và max size.
  • File endpoint trả text hay Blob/file download.

Các mục này phải lấy từ contract BE. FE không nên tự chọn vì tài liệu DES chỉ mô tả thuật toán block cơ bản, không quy định đầy đủ transport format cho ứng dụng web.
